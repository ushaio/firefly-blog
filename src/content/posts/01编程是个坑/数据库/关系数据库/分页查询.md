# SQL分页

>偏移量分页

```sql
-- ----MySQL or PostgreSQL or SQLite or 达梦----
SELECT id, name
FROM users
ORDER BY id
LIMIT 10 OFFSET 20; # 21~30条数据

-- ----MySQL----
SELECT id, name
FROM users
ORDER BY id
LIMIT 20, 10;
```
- **`LIMIT 10`**：最多返回 **10 条记录**。
- **`OFFSET 20`**：跳过查询结果的前 **20 条记录**。
>**跳过前 20 条，取接下来的 10 条，也就是第 21～30 条。** 如果剩余不足 10 条，就只返回剩余的记录。

```sql
-- ----Oracle 12c 及以后 or 达梦----
SELECT id, name
FROM users
ORDER BY id
OFFSET 20 ROWS
FETCH NEXT 10 ROWS ONLY;

-- ----Oracle 11g 等旧版本（放弃X）----
SELECT id, name
FROM (
    SELECT t.*, ROWNUM AS rn
    FROM (
        SELECT id, name
        FROM users
        ORDER BY id
    ) t
    WHERE ROWNUM <= 30
)
WHERE rn > 20
ORDER BY rn;
```

| 数据库              | 查询第 3 页、每页 10 条的分页部分                     |
| ---------------- | ---------------------------------------- |
| MySQL / MariaDB  | `LIMIT 10 OFFSET 20` 或 `LIMIT 20, 10`    |
| PostgreSQL       | `LIMIT 10 OFFSET 20`                     |
| SQLite           | 推荐 `LIMIT 10 OFFSET 20`                  |
| SQL Server 2012+ | `OFFSET 20 ROWS FETCH NEXT 10 ROWS ONLY` |
| Oracle 12c+      | `OFFSET 20 ROWS FETCH NEXT 10 ROWS ONLY` |

# 分页插件-PageHelper（AI生成）

以 **Spring Boot + MyBatis + PageHelper** 为例：你在 Java 中传入“第几页、每页几条”，分页插件负责按数据库方言生成分页 SQL，Mapper 中不再手写 `LIMIT`。([raw.githubusercontent.com](https://raw.githubusercontent.com/pagehelper-org/Mybatis-PageHelper/master/wikis/zh/HowToUse.md))

## 1. 引入分页插件

下面以 **Spring Boot 3、JDK 17+** 为例，使用官方发布的 `2.1.1` 版本。**不要直接跨大版本照搬依赖**，例如 Spring Boot 4 应选择对应适配的版本。([raw.githubusercontent.com](https://raw.githubusercontent.com/pagehelper-org/pagehelper-spring-boot/master/README.md))

```xml
<dependency>
    <groupId>com.github.pagehelper</groupId>
    <artifactId>pagehelper-spring-boot-starter</artifactId>
    <version>2.1.1</version>
</dependency>
```

假设项目已经配置好数据源和 MyBatis。引入这个 starter 后，分页拦截器会自动配置，不需要再手动注册一遍。([raw.githubusercontent.com](https://raw.githubusercontent.com/pagehelper-org/Mybatis-PageHelper/master/wikis/zh/HowToUse.md))

## 2. 配置数据库方言

以 MySQL 为例，在 `application.yml` 中配置：

```yaml
pagehelper:
  helperDialect: mysql
  reasonable: false
```

- `helperDialect`：指定使用哪个数据库的分页方式；也可以不设置，让插件自动识别。
- `reasonable: false`：不启用自动调整越界页码的功能。([raw.githubusercontent.com](https://raw.githubusercontent.com/pagehelper-org/Mybatis-PageHelper/master/wikis/zh/HowToUse.md))

## 3. Mapper 正常写查询

示例假设已有 `User` 实体，包含 `id`、`name` 属性。

```java
import org.apache.ibatis.annotations.Mapper;
import org.apache.ibatis.annotations.Select;
import java.util.List;

@Mapper
public interface UserMapper {

    @Select("""
        SELECT id, name
        FROM users
        ORDER BY id
        """)
    List<User> selectUsers();
}
```

**这里不写 `LIMIT` 或 `OFFSET`，由插件处理分页。** PageHelper 官方用法也是在普通 Mapper 查询之前设置分页参数。([raw.githubusercontent.com](https://raw.githubusercontent.com/pagehelper-org/Mybatis-PageHelper/master/wikis/zh/HowToUse.md))

## 4. Service 中开启分页

核心顺序是：**先设置分页参数 → 紧接着执行查询 → 包装分页结果**。下面额外使用 `finally` 清理当前线程的分页参数。([raw.githubusercontent.com](https://raw.githubusercontent.com/pagehelper-org/Mybatis-PageHelper/master/wikis/zh/HowToUse.md))

```java
import com.github.pagehelper.PageHelper;
import com.github.pagehelper.PageInfo;
import org.springframework.stereotype.Service;
import java.util.List;

@Service
public class UserService {

    private final UserMapper userMapper;

    public UserService(UserMapper userMapper) {
        this.userMapper = userMapper;
    }

    public PageInfo<User> listUsers(int pageNum, int pageSize) {
        // 本示例的参数约束
        if (pageNum < 1 || pageSize < 1 || pageSize > 100) {
            throw new IllegalArgumentException(
                "页码必须大于等于1，每页条数必须在1～100之间"
            );
        }

        try {
            // 第一个参数是页码，不是跳过的条数！
            PageHelper.startPage(pageNum, pageSize);

            // 紧接着执行需要分页的查询
            List<User> users = userMapper.selectUsers();

            return new PageInfo<>(users);
        } finally {
            PageHelper.clearPage();
        }
    }
}
```

调用示例：

```java
PageInfo<User> page = userService.listUsers(3, 10);
```

这里 **`3` 表示第 3 页，`10` 表示每页最多 10 条**，而不是跳过 3 条。`startPage` 接收的参数就是 `pageNum` 和 `pageSize`。([raw.githubusercontent.com](https://raw.githubusercontent.com/pagehelper-org/Mybatis-PageHelper/master/src/main/java/com/github/pagehelper/page/PageMethod.java))

对应到前面的 MySQL 分页，可以理解为：

```sql
SELECT id, name
FROM users
ORDER BY id
LIMIT 10 OFFSET 20;
```

这是**等价含义示例**，插件实际生成的 SQL 形式以数据库方言和日志为准。([raw.githubusercontent.com](https://raw.githubusercontent.com/pagehelper-org/Mybatis-PageHelper/master/wikis/zh/HowToUse.md))

## 5. 获取分页结果

`PageInfo` 不只有本页数据，还包含当前页码、每页条数、总记录数和总页数等信息。([raw.githubusercontent.com](https://raw.githubusercontent.com/pagehelper-org/Mybatis-PageHelper/master/src/main/java/com/github/pagehelper/PageInfo.java))

```java
page.getList();      // 当前页的数据
page.getPageNum();   // 当前页码：3
page.getPageSize();  // 每页条数：10
page.getTotal();     // 满足查询条件的总记录数
page.getPages();     // 总页数
```

例如，**假设共有 95 条记录**，每页 10 条，则总页数为 10；第 3 页返回排序后的第 21～30 条。

## 6. 两个重要注意点

### 分页设置后，不要插入其他查询

`startPage` 通常只作用于它后面紧接着的第一个 MyBatis 查询。如果先执行别的查询，分页参数可能被那个查询使用。([raw.githubusercontent.com](https://raw.githubusercontent.com/pagehelper-org/Mybatis-PageHelper/master/wikis/zh/HowToUse.md))

```java
// 错误示范
PageHelper.startPage(3, 10);
departmentMapper.selectAll(); // 分页可能用在这里
userMapper.selectUsers();     // 而不是这里
```

### 默认还会统计总条数

默认启用总数统计，因此通常会执行 **COUNT 查询 + 当前页数据查询**。若不需要总条数，可以关闭本次统计：([raw.githubusercontent.com](https://raw.githubusercontent.com/pagehelper-org/Mybatis-PageHelper/master/wikis/zh/HowToUse.md))

```java
PageHelper.startPage(3, 10, false);
```

**一句话记住：`startPage(3, 10)` 是“第 3 页、每页 10 条”；`LIMIT 10 OFFSET 20` 是“最多取 10 条、先跳过 20 条”。**([raw.githubusercontent.com](https://raw.githubusercontent.com/pagehelper-org/Mybatis-PageHelper/master/src/main/java/com/github/pagehelper/page/PageMethod.java))

# 分页插件-MybatisPlus（AI生成）

分页拦截器是 **`PaginationInnerInterceptor`**，需要先注册到 `MybatisPlusInterceptor`。例如使用 MySQL：([baomidou.com](https://baomidou.com/plugins/pagination/?utm_source=openai))

```java
@Configuration
public class MybatisPlusConfig {

    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() {
        MybatisPlusInterceptor interceptor =
                new MybatisPlusInterceptor();

        interceptor.addInnerInterceptor(
                new PaginationInnerInterceptor(DbType.MYSQL)
        );

        return interceptor;
    }
}
```

配置好后，假设 `UserMapper` 继承了 MyBatis-Plus 的 `BaseMapper<User>`，分页查询可以这样写：([baomidou.com](https://baomidou.com/plugins/pagination/?utm_source=openai))

```java
// 第3页，每页10条
Page<User> page = new Page<>(3, 10);

// 按id升序分页查询
userMapper.selectPage(
    page,
    Wrappers.<User>lambdaQuery().orderByAsc(User::getId)
);

List<User> users = page.getRecords(); // 本页数据
long total = page.getTotal();         // 总记录数
long pages = page.getPages();         // 总页数
```

**注意：从 MyBatis-Plus 3.5.9 起，使用该分页插件需要额外引入对应的 `mybatis-plus-jsqlparser` 依赖。** ([baomidou.com](https://baomidou.com/en/plugins/pagination/?utm_source=openai))

# 分页插件-MyBatisFlex（AI生成）

MyBatis-Flex 在 `BaseMapper` 中提供了 `paginate()` 方法，不需要沿用 PageHelper 的 `startPage()` 调用方式。([mybatis-flex.com](https://mybatis-flex.com/zh/base/query.html?utm_source=openai))

```java
// 假设UserMapper继承MyBatis-Flex的BaseMapper<User>
// USER是项目生成的表定义
QueryWrapper query = QueryWrapper.create()
    .select()
    .from(USER)
    .orderBy(USER.ID.asc());

// 第3页，每页10条
Page<User> page = userMapper.paginate(3, 10, query);

List<User> users = page.getRecords(); // 本页数据
long total = page.getTotalRow();      // 总记录数
```

这里的 `Page`、`BaseMapper` 等类来自 **MyBatis-Flex**，不要和 MyBatis-Plus 的同名类混用。([mybatis-flex.com](https://mybatis-flex.com/zh/base/query.html?utm_source=openai))


# 游标分页

>上次查到了某个 ID，这次从这个 ID 后面继续取 10 条。

## 第一批：取前 10 条

```sql
SELECT id, name
FROM users
ORDER BY id ASC
LIMIT 10;
```

假设返回的 ID 是：
```text
1、2、3、5、6、8、9、12、15、18
```
那么，下一次查询的**游标值就是 `18`**。

## 下一批：从 ID 18 后面继续查

```sql
SELECT id, name
FROM users
WHERE id > 18
ORDER BY id ASC
LIMIT 10;
```
这里：

- `18`：上一次最后一条记录的 ID，**不是页码，也不是跳过条数**。
- `id > 18`：从这个位置后面继续查。
- `LIMIT 10`：最多取 10 条。

| 对比    | 偏移量分页    | 游标／键集分页     |
| ----- | -------- | ----------- |
| 请求表达  | 第几页、每页几条 | 从哪个位置继续、取几条 |
| 查询思路  | 跳过前面的记录  | 用排序键筛选后续记录  |
| 跳到指定页 | 方便       | 通常不能直接跳到任意页 |
| 深分页   | 大偏移量可能变慢 | 有匹配索引时通常更高效 |
| 常见场景  | 带页码的列表   | 滚动加载、连续向后读取 |
|       |          |             |

## 额外考虑

游标分页本质是根据上一次查询的结果的末尾id继续向后查询，那如果下一次分页跳转的查询条件变更了的话，是否就失效了？

因此按页查询还是偏移量分页合适点。

# 使用场景

>需要“跳到第几页”，优先考虑偏移量分页；需要“从上次位置继续读”，优先考虑游标分页。

| 使用场景                | 优先考虑       | 原因                 |
| ------------------- | ---------- | ------------------ |
| 后台管理列表：用户、订单、商品管理   | **偏移量分页**  | 经常需要页码、跳页          |
| 搜索结果：跳到第 5 页、第 10 页 | **偏移量分页**  | 可以直接根据页码计算偏移量      |
| **手机端信息流、下拉加载更多**   | **游标分页**   | **通常只需要继续加载下一批**   |
| **消息记录、日志连续浏览**     | **游标分页**   | **按时间和唯一 ID 连续读取** |
| **大量数据分批处理、断点续读**   | **游标分页**   | **可以保存上次处理的位置**    |
| 既要连续翻页，又要任意跳页       | **考虑混合方案** | 连续翻页用游标，跳页用偏移量     |
