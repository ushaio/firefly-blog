# 是什么？
MongoDB 是一个**面向文档的 NoSQL 数据库**：数据以类似 JSON 的 BSON 文档形式存放，若干个文档组成一个集合（collection），而不是用表、行、列来组织。

一个文档长这样：

```json
{
  "_id": ObjectId("6505f1a2c8e4b0a1d2f3e4a5"),
  "name": "张三",
  "age": 28,
  "tags": ["程序员", "读书"],
  "address": { "city": "杭州", "district": "西湖区" },
  "createdAt": ISODate("2026-09-02T08:00:00Z")
}
```

几个关键点：

- **文档（document）**：一条数据，对应关系型数据库里的一行，但字段可以任意嵌套、嵌套数组，不用预先定义表结构（schema-less / schema-flexible）。
- **集合（collection）**：一组文档，对应关系型数据库里的表。同一集合里的文档字段可以不一样。
- **数据库（database）**：多个集合的容器，默认端口 27017。
- **BSON**：Binary JSON，MongoDB 实际存储的格式，比 JSON 多了 `ObjectId`、`Date`、`Decimal128`、二进制等类型。
- **`_id`**：每个文档必须有且唯一的主键，不指定时自动生成 `ObjectId`（内含时间戳、机器标识、进程号、计数器）。

常用操作对应关系：

| 关系型数据库（SQL） | MongoDB（MQL） |
| --- | --- |
| `INSERT INTO` | `db.coll.insertOne()` / `insertMany()` |
| `SELECT` | `db.coll.find()` |
| `UPDATE` | `db.coll.updateOne()` / `updateMany()` |
| `DELETE` | `db.coll.deleteOne()` / `deleteMany()` |

# 和其他数据库对比有什么区别？

**MongoDB 与 MySQL 这类关系型数据库最本质的区别**在“文档”上：一个业务对象的全部字段（包括嵌套对象和数组）可以只存一条记录，查出来就能直接用；关系型数据库则要把它们拆到多张表，再靠 JOIN 拼回来。

# 解决什么问题？

**这种设计解决的主要是这类问题**：数据结构经常变（需求还在试错阶段）、字段嵌套深且多态（比如不同商品的属性完全不同）、一次读写就希望拿到完整对象（查询少、读取快）；代价是弱事务、跨集合 JOIN 能力有限、缺少统一 schema 带来的数据一致性风险。

# 如何用？

先准备一个集合（用 `users`，贴近真实业务）：

```js
use demo                       // 切换/创建数据库 demo（use 后不插入数据时数据库不会真建出来）

db.users.insertOne({           // 单条
  name: "张三",
  age: 28,
  city: "杭州",
  tags: ["程序员", "读书"],
  address: { province: "浙江", district: "西湖区" },
  createdAt: new Date()
})

db.users.insertMany([          // 批量
  { name: "李四", age: 32, city: "上海", tags: ["产品"], address: { province: "上海", district: "浦东新区" } },
  { name: "王五", age: 25, city: "杭州", tags: ["程序员", "健身"], address: { province: "浙江", district: "余杭区" } },
  { name: "赵六", age: 41, city: "北京", tags: ["运营"] }
])
```

## **增（Create）**

```js
db.users.insertOne({ name: "钱七", age: 30, city: "深圳" }, { writeConcern: { w: 1 } })

// 有则更新、无则插入
db.users.updateOne(
  { name: "钱七" },          // ① 查询条件（Filter）
  { $set: { age: 31 } },     // ② 更新操作（Update）
  { upsert: true }           // ③ 开启upsert开关（默认 false）
)
```

## **查（Read）**

```js
// 条件查询：比较符 $gt/$gte/$lt/$ne/$in/$nin
db.users.find({ age: { $gte: 30 } })

// 多条件（AND）与 OR
db.users.find({ city: "杭州", age: { $lt: 30 } })
db.users.find({ $or: [{ city: "杭州" }, { age: { $gt: 40 } }] })

// 数组：包含某元素（匹配数组内任一元素）
db.users.find({ tags: "程序员" })
// 数组全部满足
db.users.find({ tags: { $all: ["程序员", "读书"] } })

// 嵌套对象：点号路径
db.users.find({ "address.district": "西湖区" })          // 嵌套字段精确匹配
db.users.find({ "address.province": "浙江", age: { $gt: 20 } })

// 存在性 / 正则
db.users.find({ address: { $exists: true } })            // 有 address 字段的
db.users.find({ name: /^张/ })                           // 姓张（可用 $regex）

// 投影：只返回指定字段（1 表示要，0 表示不要；_id 默认要，除非显式排除）
db.users.find({ city: "杭州" }, { name: 1, age: 1, _id: 0 })

// 排序 / 分页 / 计数
db.users.find().sort({ age: -1 }).skip(0).limit(2)       // age 倒序，页大小 2
db.users.countDocuments({ city: "杭州" })
db.users.distinct("city")                                // ["杭州", "上海", "北京", "深圳"]

// 只取一条
db.users.findOne({ name: "李四" })
```

## **改（Update）**

```js
// $set 部分更新
db.users.updateOne(
  { name: "张三" },
  { $set: { age: 29, "address.district": "拱墅区" } }
)

// 替换整个文档（保留 _id），注意没写的字段会被丢掉
db.users.replaceOne({ name: "李四" }, { name: "李四", age: 33, city: "上海" })
```
### $pull
```javascript
db.users.updateOne({ name: "张三" }, { $pull: { tags: "读书" } })       // 删掉元素
```
### $unset
```javascript
// $unset 删除字段
db.users.updateOne({ name: "赵六" }, { $unset: { address: "" } })
```

### $set
```javascript
// 批量更新
db.users.updateMany({ city: "杭州" }, { $set: { region: "华东" } })
```
### $addToSet
```javascript
db.users.updateOne({ name: "张三" }, { $addToSet: { tags: "游泳" } })   // 已存在则不重复加
```

### $inc
```javascript
// $inc 自增
db.users.updateOne({ name: "王五" }, { $inc: { age: 1 } })

```

### $push
```javascript
db.users.updateOne({ name: "张三" }, { $push: { tags: "游泳" } })
```

## **删（Delete）**

```js
db.users.deleteOne({ name: "赵六" })             // 只删一条
db.users.deleteMany({ city: "北京" })            // 删所有匹配
db.users.deleteMany({})                          // 清空集合（相当于 TRUNCATE）
db.users.drop()                                  // 连集合和索引一起删
```

### deleteOne：只删一条

若删除条件能命中多条记录（文档），则按照`_id`就近匹配

### deleteMany

不存在deleteOne的情况了，直接按照条件匹配删除即可



### 几个常见坑：

- **`updateOne` 不加更新操作符**（如直接写 `{ age: 29 }`）会变成“整体替换”，除 `_id` 外的字段全没了；要用 `$set`。
- **找不到文档不报错**：`matchedCount: 0` 就说明条件写错了或数据不存在，按返回值判断而不是靠异常。
- **`skip` 大偏移会慢**：深分页改用“上一页最后一条的 `_id`/排序值”做游标查询（`{ _id: { $gt: lastId } }`）。
- **数组字段精确匹配陷阱**：`{ tags: ["程序员", "读书"] }` 要求数组**完全相等且顺序一致**，只想“包含”要用 `{ tags: "程序员" }` 或 `$all`。
- **`find()` 不返回深层对象时可以加投影验证**，排查字段名拼写错误时特别有用。
