## 模块结构

![259](assets/Pasted%20image%2020261026114410.png)

### 基础设施 / 统一入口
- `ruoyi-gateway` —— Spring Cloud 网关（统一入口、鉴权、限流）
- `ruoyi-auth` —— OAuth2 授权认证中心

### 业务服务 (`ruoyi-modules/`)
- `ruoyi-system` —— 系统管理（用户、角色、菜单、部门、字典等）
- `ruoyi-gen` —— 代码生成
- `ruoyi-job` —— 定时任务调度
- `ruoyi-resource` —— 资源服务（文件 / OSS 等）
- `ruoyi-workflow` —— 工作流（Flowable）
- `ruoyi-ai` —— AI 能力模块

### 监控 / 运维 (`ruoyi-visual/`)
- `ruoyi-monitor` —— 服务监控（Spring Boot Admin）
- `ruoyi-snailjob-server` —— SnailJob 分布式任务调度平台

### 示例模块 (`ruoyi-example/`)
- `ruoyi-demo` —— Demo 示例服务
- `ruoyi-test-mq` —— MQ 测试服务

### 支撑模块
- `ruoyi-common` —— 公共工具 / 核心封装（Feign、Security、Redis、MyBatis 等）
- `ruoyi-api` —— 各服务对外 API 接口定义（System、Resource、Workflow 等）

## 部署模式：每个都是单独部署的 Spring Boot 吗？

**是的**。每个业务服务都是一个独立的 Spring Boot 应用，单独打包（`spring-boot-maven-plugin` 打成可执行 JAR）、单独部署运行。各服务通过 Nacos 注册中心互相发现，统一经由 Gateway 入口路由分发。

### 独立服务启动类对照表

| 服务    | 模块标识               | 启动类                         |
| :---- | :----------------- | :-------------------------- |
| 网关服务  | `gateway`          | `RuoYiGatewayApplication`   |
| 认证中心  | `auth`             | `RuoYiAuthApplication`      |
| 系统管理  | `system`           | `RuoYiSystemApplication`    |
| 代码生成  | `gen`              | `RuoYiGenApplication`       |
| 任务调度  | `job`              | `RuoYiJobApplication`       |
| 资源服务  | `resource`         | `RuoYiResourceApplication`  |
| 工作流   | `workflow`         | `RuoYiWorkflowApplication`  |
| AI 模块 | `ai`               | `RuoYiAiApplication`        |
| 监控服务  | `monitor`          | `RuoYiMonitorApplication`   |
| 分布式调度 | `snailjob-server`  | `SnailJobServerApplication` |
| 示例与测试 | `demo` / `test-mq` | 各自独立的 `Application`         |

> [!NOTE] 部署与运行注意事项
> - **非独立部署库**：`ruoyi-common`、`ruoyi-api` 不是服务，仅作为依赖库供其他服务引用（Common 是公共封装，API 是 Feign 接口定义），不含独立启动类。
> - **特殊模块**：`ruoyi-snailai-server`（AI 服务端）及部分 `demo` / `test-mq` 可能作为普通 JAR 依赖引入。
> - **最简运行依赖**：本地轻量启动仅需 **`nacos` + `gateway` + `auth` + `system`** 4 个进程，其余模块按需启动。

## Common 模块的处理机制

Common 采用 **「普通 Maven 依赖库 + 分层拆分」** 的方式处理，本质是聚合类库而非独立运行的服务。

### 模块结构拆分

`ruoyi-common` 的打包类型为 `packaging=pom`，作为一个聚合父模块，下挂 34 个子模块，按技术维度拆分：

| 类别           | 包含子模块与职能                                                                                |
| :----------- | :-------------------------------------------------------------------------------------- |
| **基础核心**     | `core`（工具类、常量、异常、统一返回）、`json`、`encrypt`、`sensitive`（脱敏）                                 |
| **Web / 接口** | `web`（全局异常、跨域、响应体包装）、`doc`（Swagger / Knife4j）、`translation`（字典翻译）                       |
| **数据持久层**    | `mybatis`（分页、多数据源）、`redis`、`elasticsearch`                                              |
| **安全认证**     | `security`、`satoken`                                                                    |
| **微服务通信**    | `dubbo`（RPC）、`nacos`、`seata`（分布式事务）、`loadbalancer`、`bus`（配置总线）                          |
| **业务支撑**     | `log`（操作日志）、`excel`（导入导出）、`oss`、`sms`、`mail`、`push`、`job`                               |
| **系统监控**     | `prometheus`、`logstash`、`skylog`                                                        |
| **其他扩展**     | `ai`、`mcp`、`mqtt`、`liteflow`、`social`（第三方登录）、`service-impl`、`bom` / `alibaba-bom`（依赖管理） |

### 使用与装配方式

- **按需引入**：没有启动类、不独立部署。各业务服务在其 `pom.xml` 中按需引入（例如 `ruoyi-system` 引入了 `ruoyi-common-nacos`、`ruoyi-common-web`、`ruoyi-common-mybatis`、`ruoyi-common-redis` 等 12 个 Common 子模块）。
- **打包产物**：子模块编译产物是标准 JAR，打包业务服务时通过 `spring-boot-maven-plugin` 重新打包打入 Fat JAR。
- **自动装配**：每个 Common 子模块内部多通过 `spring.factories` 或 `@AutoConfiguration` 实现自动装配（如 `web` 提供全局异常处理、`mybatis` 提供分页插件），业务服务引入依赖后即自动生效。
- **核心优势**：
  - **服务轻量化**：`gateway`、`auth` 仅引入所需依赖（如 Nacos、Redis、Security），避免全量依赖导致包体积臃肿；
  - **版本统一步调**：公共逻辑变更仅需在 Common 升级版本，各服务只需更新版本号即可。

---

## 业务服务引用 Common 的实践

每个 Spring Boot 服务在其 `pom.xml` 中按需声明依赖，版本由父工程 POM 统一管理（`dependencyManagement`），因此子模块中无需指定 `<version>`：

```xml
<dependency>
    <groupId>org.dromara</groupId>
    <artifactId>ruoyi-common-web</artifactId>
</dependency>
```

### 各服务的依赖差异对照

| 服务 | 典型引入的 Common 模块 | 依赖定位与特点 |
| :--- | :--- | :--- |
| `ruoyi-system` | 约 12 个：`web`、`mybatis`、`redis`、`dubbo`、`security`、`log`、`excel` 等 | 完整全栈业务依赖 |
| `ruoyi-gateway` | 少量：`redis`、`nacos`、`doc`、`sentinel` 等 | 专注网关转发，不依赖持久层与数据库驱动 |
| `ruoyi-auth` | `redis`、`security`、`satoken` 等 | 专注鉴权认证，无需引入 MyBatis |
| `ruoyi-job` | `job`、`web`、`quartz` 相关 | 专注任务调度与监控 |

> [!TIP] 按需引入的设计哲学
> **引入才会生效**：不需要操作日志就不引入 `ruoyi-common-log`，不需要数据脱敏就不引入 `ruoyi-common-sensitive`。各服务在编译构建时通过本地仓库 / Reactor 引用这些 Common 子模块的 JAR，最终一同打入自身的可执行 Fat JAR 中交付部署。

# 部署

## 一、服务器硬件配置

### 1. 环境要求（软件层）

| 项目 | 要求 |
|---|---|
| 操作系统 | CentOS 7.9+ / RockyLinux 9 / Ubuntu 22.04（推荐 Linux，Docker 部署） |
| JDK | **21+**（项目 `<java.version>21</java.version>`，且开启了虚拟线程，必须 JDK 21） |
| Maven | 3.8+（仓库自带 `mvnw`） |
| 容器 | Docker 20+ / Docker Compose v2（推荐容器化部署） |

### 2. 硬件配置（按规模分档）

| 规模         | CPU       | 内存          | 磁盘         | 适用场景                                                    |
| ---------- | --------- | ----------- | ---------- | ------------------------------------------------------- |
| **开发/测试**  | 2 核       | 4 GB        | 40 GB      | 只跑 nacos + mysql + redis + auth + system + gateway 最小闭环 |
| **小型生产**   | 4 核       | 8 GB        | 100 GB SSD | 全套业务服务，几百并发                                             |
| **中型生产**   | 8 核       | 16 GB       | 200 GB SSD | 全服务 + MQ + MinIO + 监控，几千并发                              |
| **大型/高可用** | 8 核 × N 台 | 16 GB × N 台 | 500 GB+    | 多节点集群 + 中间件独立部署                                         |

### 3. 内存占用估算（单机全量部署参考）

| 组件 | 建议堆内存 | 实际占用 |
|---|---|---|
| gateway | 512 MB | ~600 MB |
| auth | 512 MB | ~700 MB |
| system | 1 GB | ~1.2 GB |
| gen | 256 MB | ~400 MB |
| job | 512 MB | ~600 MB |
| resource | 512 MB | ~600 MB |
| workflow（Flowable 较重） | 1 GB | ~1.2 GB |
| ai | 512 MB | ~600 MB |
| monitor | 256 MB | ~400 MB |
| Nacos | 512 MB | ~600 MB |
| MySQL 8 | 1 GB（buffer pool 512M） | ~1.2 GB |
| Redis | 512 MB | ~500 MB |

> **合计约 12~14 GB**，所以中型生产建议 **16 GB 起步**；若只跑最小闭环（nacos+mysql+redis+auth+system+gateway）**8 GB 足够**。全量扩展组件（ELK、SkyWalking、RocketMQ、Kafka）每个还要再加 1~2 GB，建议拆机部署。

## 二、部署拓扑

### 单机部署（个人/小团队，推荐起步）

所有服务 + 中间件全部跑在一台服务器，用 `script/docker/docker-compose.yml` 一条命令拉起，管理成本最低。8 核 16G 即可。

### 集群部署（生产）

```
        ┌─ Nginx (80/443) ── 负载均衡 + SSL
        │
   ┌────┴────┐
   │ Gateway ×2（8080）
   └────┬────┘
        │
   ┌────┴─────────────────────┐
   │ auth / system / gen / job │
   │ resource / workflow / ai  │  ← 按服务拆分到不同节点
   └────┬─────────────────────┘
        │
   中间件独立部署：
   ├── MySQL（主从 + 定期备份）
   ├── Nacos ×3（集群模式，MySQL 持久化）
   ├── Redis（主从 / Sentinel）
   └── MinIO（分布式，至少 4 节点）
```

多节点注意事项：
- **Nacos 集群模式**：`MODE: cluster`，且必须把配置存储改为外部 MySQL（单机模式默认用内置 Derby，重启即丢配置）
- **Seata Server**：需要独立部署并注册到 Nacos，各服务通过 `tx-service-group` 找到 TC
- **服务无状态**：所有服务都不存本地状态（Sa-Token 走 Redis 共享），可直接水平扩容
- **网关多实例**：前面必须加 Nginx/LVS 做入口负载，否则 8080 单点

## 三、网络与安全组（防火墙）

只开放必要端口，内网服务不暴露公网（Sa-Token 配了 `check-same-token: true`，也不允许绕过网关直连内网服务）：

| 端口 | 服务 | 是否对外 |
|---|---|---|
| 80 / 443 | Nginx | ✅ 公网 |
| 8080 | Gateway（可只暴露给 Nginx） | ⚠️ 内网 |
| 8848 / 9848 | Nacos 控制台 | ⚠️ 仅管理内网，**切勿暴露公网** |
| 3306 | MySQL | ❌ 仅容器内网 |
| 6379 | Redis | ❌ 仅容器内网 |
| 9100 | Monitor | ⚠️ 内网 |
| 8800 / 8900 | SnailJob / SnailAI | ⚠️ 内网 |

> 安全组最小化原则：对外只留 80/443，其余全部走内网或白名单 IP。

## 四、磁盘规划

| 目录 | 内容 | 建议大小 |
|---|---|---|
| `/var/lib/mysql` | 数据库文件 | 50 GB+，务必选 SSD |
| `/docker/nacos` | 注册/配置中心日志 | 5 GB |
| `/docker/minio` | 对象存储文件 | 按业务量，独立数据盘 |
| `/docker/xxx/logs` | 各服务日志 | 20 GB，配 `logrotate` 轮转 |
| 备份目录 | mysqldump、配置导出 | 与数据盘同容量 |

> 日志是隐形杀手，一个服务一天能写几个 GB，必须配日志切割（logback 自带 `maxHistory`）+ 定时清理。

## 五、生产部署建议

- **容器化优先**：`docker-compose` 起中间件，业务服务也打成镜像，升级只需换镜像版本
- **JVM 参数**：容器内用 `-XX:MaxRAMPercentage=75` 而不是固定 `-Xmx`，避免容器内存超限被 OOM Kill
- **MySQL 必开binlog**：用于主从复制和误操作恢复，`expire_logs_days` 设 7 天
- **Redis 必设密码**：`requirepass`，否则等于把钥匙插门上
- **配置文件不要打进镜像**：Nacos 里的配置单独维护，改配置不用重新发版
- **备份三件套**：MySQL 定时全量 + binlog 增量、Nacos 配置导出、MinIO 数据同步

## 六、项目侧配置要点

每个服务本地 `application.yml` **只保留最小骨架**，真正配置全部放 Nacos：

```yaml
server:
  port: 8080
spring:
  application:
    name: ruoyi-gateway   # 应用名 = Nacos 配置文件名
  config:
    import:
      - optional:nacos:application-common.yml   # 公共配置（所有服务共享）
      - optional:nacos:${spring.application.name}.yml  # 各服务私有配置
```

`script/config/nacos/` 下的文件需要**手动导入 Nacos 控制台**（README 也写明了这一点）：

| 配置文件 | 内容 |
|---|---|
| `application-common.yml` | 全局共享：虚拟线程、Dubbo、Redisson、Sa-Token jwt 密钥、MyBatis-Plus、接口加解密密钥、seata 开关等 |
| `datasource.yml` | 各服务数据源 URL、账号密码、Hikari 连接池参数 |
| `ruoyi-gateway.yml` | 网关路由表（Path → lb://服务名）、白名单、HttpClient 连接池 |
| `ruoyi-auth.yml` / `ruoyi-system.yml` / `ruoyi-job.yml` / `ruoyi-gen.yml` / `ruoyi-resource.yml` / `ruoyi-workflow.yml` / `ruoyi-ai.yml` / `ruoyi-monitor.yml` | 各服务私有配置 |

| 服务 | 端口 | 依赖 |

## 八、可选扩展（按需）

- **MinIO** :9000/9001 — 资源服务（OSS）需要
- **Seata** :8091 — 分布式事务，默认 `enabled: false`，用的时候再开
- **RabbitMQ / RocketMQ / Kafka** — 用了 `ruoyi-common-bus` 消息总线或 demo 才需要
- **ELK（ES+Kibana+Logstash）**、**SkyWalking**、**Prometheus + Grafana** — 日志收集与链路追踪
- **SnailJob / SnailAI** — 分布式任务调度、AI 服务端
- **Nginx** :80/443 — 前端静态资源 + 反向代理

## 九、最小启动顺序

```
1. MySQL（执行 sql 脚本）
2. Nacos（导入 script/config/nacos/ 下的配置）
3. Redis
4. ruoyi-auth（9210）
5. ruoyi-system（9201）
6. ruoyi-gateway（8080）
```

> 认证与系统服务是最小闭环；gen/job/workflow/ai 等按业务需要再启动。注意 Sa-Token 配置了 `check-same-token: true`，**不允许绕过网关直接访问内网服务**，所以对外必须走 8080。
