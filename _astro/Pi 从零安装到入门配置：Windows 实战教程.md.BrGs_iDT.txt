## 先说最终效果

如果你按照这篇文章一步步跟着配置，最终复刻出来的，是一套 Windows 下默认用 PowerShell 7、兼容 OpenAI / Anthropic 风格中转站、带全局 `AGENTS.md`、并且把权限、回退、搜索、网页访问、Markdown 预览这些基础能力先补齐的 Pi。同时你可以按需加上 subagents、MCP、todo、memory、plan mode 这些进阶能力；MCP 也会按 `eager` / `lazy` 分层。关键配置我都拆成了可以公开分享的脱敏模板

至少对我自己来说，这套工作流把这些东西补齐之后，日常用起来已经很顺了，而且整套配置的可控感会比之前更强。

## 一、先安装 Pi 本体

官方安装命令：

```powershell
npm install -g --ignore-scripts @earendil-works/pi-coding-agent
```

装完之后，先不要急着装任何 package，也先别急着在 `/login` 上来回点

如果你本来就是走官方订阅路线，比如 ChatGPT Plus / Pro、Claude Pro / Max、GitHub Copilot，那一段官方自己已经写得很全了，直接看 [Providers 文档](https://pi.dev/docs/latest/providers) 就行

这篇后面就不展开官方订阅了，本篇主要来放在 中转站 / relay / 自定义 provider 这条线上

所以我建议你装完 Pi 之后，先把模型和中转配置好，再正式进第一次可用状态

## 二、先把模型和中转站配好

这一节我建议你不要偷懒去抄我的配置，因为我不知道你看到这篇文章的时候新模型已经出现到哪了

我自己的做法很简单，就是直接开官方模型目录：

- [模型目录](https://pi.dev/models)
- [模型配置文档](https://pi.dev/docs/latest/models)
- [全局设置文档](https://pi.dev/docs/latest/settings)

**如果你看到这里已经开始头大了，最省事的办法就是把这三个链接连同你自己的需求一起丢给 AI，让它按官方文档直接帮你生成一版 `settings.json` 和 `models.json`，你再回来按需微调**

顺序也很直接：先在 `pi.dev/models` 找你实际打算用的 provider 和 model，再点进详情页确认**精确 model id、上下文窗口、价格、输入模态**，最后再决定你是走“内置 provider 改 `baseUrl`”还是“自定义 provider + 自己声明 models”

我自己现在主要是中转站路线，所以大多数时候用的是第一种。说白了，如果你的中转站本质上是 **OpenAI 兼容**，那就继续用 provider 名 `openai`；如果本质上是 **Anthropic 兼容**，那就继续用 `anthropic`。这种情况下通常只需要改 `baseUrl`，真要自己改的是用 `modelOverrides` 补上下文窗口、token 上限之类的信息

这一套的好处是最省事，`/model` 里内置模型体系还能继续直接用

这一步你真正需要先关心的，其实只是 `settings.json` 里这几个键：

```json
{
  "defaultProvider": "openai",
  "defaultModel": "gpt-5.6-terra",
  "enabledModels": [
    "gpt-5.5",
    "gpt-5.6-luna",
    "gpt-5.6-terra",
    "gpt-5.6-sol",
    "claude-sonnet-4-6",
    "claude-opus-4-8"
  ]
}
```

然后再看 `~/.pi/agent/models.json` 里 provider 这层：

```json
{
  "providers": {
    "openai": {
      "baseUrl": "<YOUR_OPENAI_COMPAT_BASE_URL>",
      "modelOverrides": {
        "gpt-5.6-luna": {
          "contextWindow": 1050000
        },
        "gpt-5.6-terra": {
          "contextWindow": 1050000
        },
        "gpt-5.6-sol": {
          "contextWindow": 1050000
        }
      }
    },
    "anthropic": {
      "baseUrl": "<YOUR_ANTHROPIC_COMPAT_BASE_URL>"
    }
  }
}
```

**完整 `settings.json` 和 `models.json` 我统一放在第十一节**

注意，`contextWindow` 不要机械照抄我这篇里的数字，最好直接按你在 `pi.dev/models` 里选中的那个 provider 详情页来填。第二，`defaultProvider: "openai"` 不等于你在走官方 OpenAI 订阅，它只是说明你当前这一组模型按 OpenAI 风格 API 在说话。第三，上面这段里的 `baseUrl` 是占位符

如果你不是用 `openai` / `anthropic` 这种内置 provider 名，而是准备自己起一个自定义 provider，那就直接回官方 `Custom Models` 文档看。因为我自己当前真实配置不是那条路，这篇就不再额外展开一套和我现用配置无关的示例了

## 三、Windows 下把默认 shell 切到 PowerShell 7

Pi 官方 Windows 文档现在还是明显偏向 Bash

但是我自己这次实际折腾下来，最后是把 Pi 切到 PowerShell 7 了。做法就是在你刚才那个 `~/.pi/agent/settings.json` 里继续补 `shellPath`。

如果你不确定 PowerShell 7 的路径，先查：

```powershell
Get-Command pwsh
```

然后把 `settings.json` 里的相关部分补成这样：

```json
{
  "shellPath": "C:\\Program Files\\PowerShell\\7\\pwsh.exe"
}
```

完整 `settings.json` 同样统一放在第十一节

还有一点也别太理想化，即便你切到了 PowerShell 7，也不要天真地以为所有模型从此就会完全按 PowerShell 脑回路输出命令，Git Bash 我建议还是装着，必要时当兜底

---

到这里再找个空目录试启动一次：

```powershell
mkdir pi-playground
cd pi-playground
pi
```

第一次启动我建议只做这几件事：

1. `/model`，确认你刚才启用的模型都能看到
2. 给它一个只读任务，确认目录读取和基本对话正常
3. 如果你走的是官方订阅路线，这时候再补 `/login`

这一轮能跑通，再继续下面的配置。否则先回官网看 `providers`、`models`、`settings` 这三页

## 五、我现在实际在用的 package

安装：

```powershell
pi install npm:@gotgenes/pi-permission-system
```

Pi 默认是不带权限控制的，这个 package 就是用来补齐权限控制。后面你会看到，我给它单独配了 `config.json`，把“哪些能读、哪些要问、哪些直接不许碰”控制好

## 六、配置索引

这篇后面只有几处地方会放完整配置，其余流程章节如果需要解释，只会截相关片段。你可以按下面这个索引跳着看：

1. 第七节看 `@gotgenes/pi-permission-system`
   对应 `~/.pi/agent/extensions/pi-permission-system/config.json`

2. 第八节看 `pi-subagents`
   对应 `~/.pi/agent/settings.json` 里的 `subagents` 片段
   以及 `~/.pi/agent/extensions/subagent/config.json`

3. 第九节看 `pi-mcp-adapter`
   对应 `~/.pi/agent/mcp.json`

4. 第十节看长会话压缩和 `pi-observational-memory`
   对应 `~/.pi/agent/settings.json` 里的 `compaction` 和 `observational-memory`

5. 第十一节看完整全局配置
   对应 `~/.pi/agent/settings.json` 和 `~/.pi/agent/models.json`

注意不是每个 package 都有独立配置文件，像 `pi-rewind`、`pi-wtf`、`pi-web-access`、`pi-markdown-preview`、`rpiv-todo`、`rpiv-advisor`、`pi-zentui` 这类包，大多数装完就能用。

这里我强调三个关键点：

## 八、subagents 怎么配

`pi-subagents` 它只是给 Pi 增加了 delegation 能力，你还得自己把模型、并发和提示词习惯配好

我现在的 `settings.json` 里，subagents 这块是这样的：

[details="settings.json 里的 subagents 配置"]
```json
{
  "subagents": {
    "defaultModel": "gpt-5.6-luna",
    "agentOverrides": {
      "delegate": {
        "model": "gpt-5.6-luna",
        "thinking": "low"
      },
      "scout": {
        "model": "gpt-5.6-luna",
        "thinking": "low"
      },
      "context-builder": {
        "model": "gpt-5.6-luna",
        "thinking": "medium",
        "fallbackModels": [
          "gpt-5.6-terra"
        ]
      },
      "researcher": {
        "model": "gpt-5.6-luna",
        "thinking": "medium",
        "fallbackModels": [
          "gpt-5.6-terra"
        ]
      },
      "planner": {
```

## 九、MCP 怎么配

我当时配置好 `pi-mcp-adapter` 把 Codex 的 MCP 迁到 Pi，第一眼看到 `0/N` 还以为迁移没生效。后来查 README 才意识到，默认 MCP 加载 是 lazy 的

如果你也准备配 MCP，我建议先把“共享 MCP 配置”和“Pi 专属覆盖”分开。跨工具共用的放 `~/.config/mcp/mcp.json`，Pi 自己的覆盖层放 `~/.pi/agent/mcp.json`。

我当前 `~/.pi/agent/mcp.json` 的思路是：

## 十、长会话和压缩怎么配

这块我更建议你现在别先抄我的数字，而是先回 [Pi 模型目录](https://pi.dev/models) 看你当前模型到底支持多大的上下文窗口，再按那个长度去反推自己的压缩和 memory 触发线。一个比较稳的起手式，就是先按大约 80% 去设。比如某个模型你确认能吃 `1,000,000` tokens，那你的主要触发线就可以先往 `800,000` 左右去靠，再结合自己的实际工作流慢慢微调。

我现在的配置是：

[details="compaction 和 observational-memory 配置"]
```json
{
  "compaction": {
    "enabled": true,
    "reserveTokens": 32768,
    "keepRecentTokens": 48000
  },
  "observational-memory": {
    "observeAfterTokens": 30000,
    "reflectAfterTokens": 90000,
    "compactAfterTokens": 200000,
    "compactAfterTokensMode": "ratio",
    "compactAfterTokensRatio": 0.8,
    "observationsPoolMaxTokens": 32000,
    "observationsPoolTargetTokens": 16000,
    "agentMaxTurns": 16,
    "passive": false,
    "debugLog": false
  }
}
```
[/details]

上面这一组是我当前的实配，和我自己的模型、relay、工作习惯有关。这里这组值更适合拿来参考字段怎么写，而不是直接当成唯一标准答案，我还是建议先去官网确认你当前模型支持的上下文长度，再把 `compaction` 和 memory 的关键触发线按 80% 左右去设
